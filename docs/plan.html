1Context & Research

The user is exploring buildable project ideas for their Claude Code subscription. Initial research (via Grok) flagged "Letterboxd for video games" as a recurring evergreen wish on X, with Backloggd as the closest existing solution but with notable execution gaps.

We cross-verified this research with three parallel research agents. Here's what held up versus what didn't.

What was verified

  • Demand is real and persistent into May 2026 — the wish keeps surfacing despite Backloggd existing.
  • Backloggd is the leader: 650K+ users, 31.5M games logged, solo dev now full-time on Patreon (1,300+ backers).
  • "No native mobile" is a confirmed top complaint.

What turned out wrong or outdated

  • Backloggd does not have an official iOS app — what Grok saw was "Backloggr," a third-party competitor.
  • Specific vote counts (16k Android / 14k Steam / 12k recs) appear hallucinated.
  • The recommendations gap was partially closed in June 2025 when Backloggd shipped a Discovery Engine.
  • The competitive landscape is significantly more crowded than Grok knew — at least 15 active competitors: IGN Playlist, GameTrack, Gamery, SavePoint, Stash, Spawnr, KTOMG, GAMEYE, Gamepal, Sofa, RAWG, Backlog Buddy, etc.

The actual remaining gaps

  1. Native Android with strong network effects — Backloggd has the social graph but no Android.
  2. PSN sync is fundamentally hard — no official Sony API, only fragile unofficial libraries.
  3. Switch sync is impossible via API — manual entry only.
  4. No competitor combines polished modern UI + serious AI features + robust social network in a single web-first product.
  5. Nobody combines premium pixel-art aesthetic + AI mascot character + Raycast-class polish — an unclaimed visual position. This is our unique angle.
Intended outcome: Ship a polished, distinctive AI-first game tracker that competes on craft and AI quality rather than network effects. Phased delivery so each milestone is shippable on its own. Architecture supports the full vision from day one; shipping is staged.

Tech stack details

  • Framework: Next.js 15 (App Router), TypeScript strict mode
  • Styling: Tailwind CSS v4, shadcn/ui primitives, tw-animate-css
  • Animation: Framer Motion (mascot, transitions, micro-interactions)
  • Data fetching: TanStack Query v5 client-side, RSC for server-side
  • Client state: Zustand for ephemeral UI state
  • Forms: React Hook Form + Zod schema validation
  • Database: Supabase Postgres with Row-Level Security on every table
  • ORM: Drizzle ORM (better DX than raw Supabase JS for typed queries)
  • Auth: Supabase Auth (email/password + magic link), session in cookies
  • File storage: Supabase Storage for avatars, custom covers, mascot variants. RAWG covers used by URL.
  • Email: Resend (3K/mo free) for transactional
  • Pixel-art: Sprite sheets + CSS animations, Framer Motion for state transitions
  • Charts: recharts or visx for taste fingerprint visualization
  • Observability: Vercel Analytics free + Sentry free
  • AI SDK: Vercel AI SDK (ai) — provider-agnostic abstraction
  • Background jobs: Vercel Cron + Supabase Edge Functions

AI Provider Router pattern

A single aiProviderRouter module exposes one async function. Tries providers in order, falls back on rate-limit errors:

generate(prompt, opts)
  → try Cerebras (Llama 3.3 70B, 1M tokens/day free)
  → on 429/5xx → try Groq (Llama 3.3 70B, 14,400 req/day free)
  → on 429/5xx → try Cloudflare Workers AI (10K Neurons/day free)
  → on 429/5xx OR opts.quality === 'premium' → DeepSeek V3 ($0.14/$0.28 per M)
  → if all fail → throw with user-friendly message

Same prompt template works on every provider (Llama 3.3 70B is the common denominator). Includes:

  • Token-bucket rate limiter per provider per minute
  • Daily counter to preempt provider exhaustion
  • Cost telemetry to Supabase (track $ spent per user per feature)
  • Caching layer (Vercel KV) — semantic cache on prompt hash to avoid duplicate calls
Skip these providers: Gemini free (trains on data), OpenRouter free (50 RPD), GitHub Models (no production use), Anthropic free credits ($5 trial only).

4Data Model

Postgres via Supabase, managed with Drizzle migrations. All user-owned tables enforce auth.uid() = user_id via RLS for writes; public reads scoped by is_public flags.

Core auth + profile

  • auth.users — Supabase managed
  • profiles — username, display_name, bio, avatar_url, mascot_variant, is_public

Games (RAWG-cached catalog)

  • games — slug, title, released, cover_url, screenshot_urls, description, genres[], themes[], mechanics[], platforms[], playtime_avg_hours, metacritic, rawg_rating, cached_at
  • game_aliases — alternate titles for search

User logs (the core "I played this" record)

  • logs — status, rating (0–10), started_at, finished_at, hours_played, platform_played_on, is_replay, is_private

Reviews

  • reviews — body, rating, is_ai_assisted, published_at, is_public, optional log_id link
  • review_questions — the AI interview Q&A used to draft the review

AI taste fingerprint

  • taste_fingerprints — genre/theme/mechanic vectors (jsonb), length_preference, difficulty_preference, narrative_summary, model_version, generated_at
  • recommendations — score, reason, algorithm (similarity|ai|hybrid), generated_at, dismissed

Social

  • follows, likes, comments (one-level threading)
  • lists + list_items (curated game collections)
  • notifications — type, target_id, actor_id, read_at

Library imports

  • platform_connections — platform, external_id, encrypted access/refresh tokens, last_synced_at
  • imports — status (queued|running|completed|failed), counts, error_message

Operational

  • ai_calls — telemetry: feature, provider, model, tokens, cost_usd, latency_ms
  • year_in_reviews — payload (jsonb), share_image_url

5Phased Roadmap

Each phase ends with a working, deployable milestone. Database schema is created in full at Phase 0 — features fill in tables over time. Strict phase gates: nothing in phase N+1 begins until phase N ships to staging.

Phase 0 — Foundation Weeks 1–2

  • Initialize Next.js 15, Tailwind v4, Supabase project, Drizzle
  • Full database schema migration (all tables, even unused yet)
  • Supabase Auth wired (email + magic link), protected route wrapper
  • Design system foundation: tokens, dark mode, shadcn/ui setup
  • Mascot system stub: pixel-art placeholder + state machine via Framer Motion
  • Login/signup pages, deploy to Vercel staging with preview deploys per PR
Verify: Visit staging URL → sign up → log in → see authenticated home page with mascot waving.
Phase 1 — Core Logging Weeks 3–6

A useful personal game tracker. End of phase = you can dogfood it.

  • RAWG API client wrapper (rate-limited, cached via Vercel KV)
  • Game search UI: typeahead → results grid with cover art
  • Game detail page with "log it" CTA
  • Log creation flow: status, rating, dates, platform, hours, notes
  • Personal library page: filter by status, sort by rating/date, list/grid views
  • Profile page (own): stats summary, recent activity timeline
  • Pixel-art empty states with mascot ("No games yet — let's log one!")
Verify: Search for "Hades" → log it as completed with rating 9 → see it on personal library page filtered by "completed."
Phase 2 — AI Reviews Weeks 7–10

First AI magic moment. End of phase = soft launch to friends.

  • AI provider router with all four providers wired
  • Token bucket rate limiter + daily counters + cost telemetry
  • Review writing flow: AI interview (3–4 questions) → draft → user edits → publish
  • Mascot animates as it "listens" during the interview
  • Public review URLs (/u/{username}/reviews/{slug}) — shareable
  • Review reactions: like only (comments come in Phase 5)
  • AI provider failover testing (force-disable Cerebras, verify Groq takes over)
Verify: Log a completed game → click "Write with mascot" → answer 4 questions → get draft → edit → publish → visit public URL → friend reads it from a Discord link.
★ Milestone: Soft personal launch + share with friends
Phase 3 — Library Imports Weeks 11–14

Remove the #1 friction (manual entry) for new users.

  • Adapter interface: LibraryImporter with connect/fetchLibrary/disconnect
  • Steam adapter (Steam Web API, OpenID for connection)
  • Xbox adapter (OpenXBL, with clear "unofficial" disclosure)
  • PSN adapter (psn-api, labeled Beta)
  • Manual platform: Switch + physical games (barcode-scanner future hook)
  • Background sync: Supabase Edge Function on cron, paginated with progress UI
  • Conflict resolution: prefer user data, merge platform list
  • Settings → "Connected Platforms" with sync status, last-synced timestamps
Verify: Connect Steam → see import progress → end up with 200 games auto-logged at "backlog" status → see merge with previously manually-logged Hades.
Phase 4 — Taste Fingerprint + Recommendations Weeks 15–20

The differentiating feature that justifies the "AI-first" claim.

  • Fingerprint generator pipeline (triggers at 10+ logs or on-demand)
  • Aggregates logs+reviews+ratings → structured genre/theme/mechanic vectors
  • AI generates narrative summary ("You love narrative-driven indies with strong art direction…")
  • Fingerprint visualization: pixel-art "taste DNA" infographic, charts, mascot reads narrative
  • Shareable as image card via Vercel OG (server-rendered)
  • Hybrid recommendation engine: metadata similarity → AI re-ranking with reasoning
  • "What should I play next?" page: filter by mood, time available, platform owned
  • Per-recommendation feedback ("sounds great" / "not for me") improves future recs
Verify: With 30+ logs → see fingerprint with non-trivial narrative → get 5 recommendations with cogent reasons → share fingerprint image card to social media.
Phase 5 — Social Layer Weeks 21–26

Network effects layer. Letterboxd-equivalent feature parity.

  • Follow / unfollow (asymmetric, like Twitter/Letterboxd)
  • Public profile pages: library, recent reviews, fingerprint, lists
  • Activity feed: chronological logs/reviews/ratings from followed users
  • Threaded comments on reviews (one level deep)
  • Lists: curated collections, reorderable, optional notes per item, public/private
  • Notifications: new follower, review liked, comment, friend logged your wishlist game
  • Notification preferences (email digest vs in-app)
  • Discovery: "popular this week," "people with similar taste"
  • Basic moderation: report content, block user, simple auto-flag for spam
Verify: Two test accounts follow each other → see activity in feed → comment on reviews → get notifications → create and share a list.
★ Milestone: Beta launch — Letterboxd-equivalent feature parity

  • Top games, surprises, taste evolution, longest, most-replayed
  • Shareable image cards optimized for Twitter / Instagram / Discord
  • Public year-in-review URLs (/u/{username}/year/2026)
  • Monthly mini-recaps as bonus engagement loop
  • Editorial highlights ("staff picks of 2026") for credibility
Verify: Generate year-in-review → watch animated narrative → download share card → post to Twitter → card renders correctly with OG meta.

6UX Flow Highlights

Onboarding

  1. Sign up → mascot greets ("Hey, I'm [name]!")
  2. Pick username + display name
  3. Optional: choose mascot color variant
  4. "Let's log your first game" — search prompt with mascot pointing
  5. After first log: "Want me to help you write a review?" (introduces AI)
  6. After 5 logs: "Want to import from Steam to get started faster?" (introduces imports)

Write a review with the mascot

  1. From a completed log, click "Write with mascot"
  2. Mascot animates "thinking" → asks first question
  3. Conversational UI: each Q&A in a card, mascot animates between
  4. After 3–4 questions, mascot says "Drafting your review…"
  5. Draft appears, full edit control, mascot waits patiently
  6. Publish → mascot celebrates, share modal opens

What should I play next?

  1. From dashboard, click "What should I play?"
  2. Mascot asks: "How long do you have?" (15min / 1hr / 3hr+ / multi-session)
  3. "Mood?" (chill / challenged / story-driven / mindless / multiplayer)
  4. "Platform?" (defaults to your most-recently-used)
  5. Mascot returns 3–5 recommendations with reasoning, each with "play this" / "skip" / "save"

Year-in-review

  1. Email arrives end of December: "Your 2026 in games is ready"
  2. Click → animated full-screen experience
  3. Mascot narrates each section (taste evolution, top games, surprises)
  4. End screen: "Share your 2026" with optimized cards for each platform

10Verification

Per-phase

Each phase ends with the explicit verification checklist defined in its phase section. A phase is "shipped" only when:

  1. Verification checklist passes on staging
  2. Lighthouse score ≥85 on key pages
  3. No TypeScript errors, no console errors in browser
  4. Core flows tested manually on Chrome + Safari + Firefox
  5. Deployed to production (Vercel) without errors
  6. Self-test: 30 minutes of usage as a real user

End-to-end (post Phase 7)

Full user journey:

  1. Anonymous user lands on homepage → mascot intro → sign up
  2. Connect Steam → import 100+ games
  3. Log a recent completed game with rating
  4. Write AI-assisted review → publish
  5. View fingerprint → see narrative summary
  6. Get 3 recommendations → mark one as "play next"
  7. Follow another user, see their activity
  8. Generate year-in-review preview → share card
If any step in this journey breaks, public launch is blocked.
